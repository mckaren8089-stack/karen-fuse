# Karen Fuse — V0.4

وب‌اپ/PWA فارسی برای پایش چندمنبعی طلای ۱۸ عیار، دلار آزاد و اونس جهانی، همراه نمودارهای تعاملی، کالیبراسیون دستی Blu و پیش‌فاکتور خرید/فروش طلا.

## معماری بازار

- **طلای ۱۸ و دلار ایران** از چند منبع عمومی جمع‌آوری و با اجماع مقاوم در برابر پرت‌ها نرمال می‌شوند.
- **XAU/USD** از منابع عمومی مستقل جمع‌آوری می‌شود و فقط Observation سالم وارد اجماع می‌شود.
- وضعیت هر دارایی برای هر منبع مستقل است: `OK`، `STALE`، `ERROR` یا `MISSING`.
- زمان Snapshot، زمان Collector و زمان اعلام‌شده توسط Provider از هم جدا هستند.
- Bid/Ask دلار هرجا واقعاً وجود داشته باشد بدون تبدیل به یک عدد واحد حفظ می‌شود.
- GitHub Actions زمان‌بندی اسمی پنج‌دقیقه‌ای دارد، اما Real-time تضمین‌شده نیست؛ شکاف‌های زمانی پنهان یا با دادهٔ ساختگی پر نمی‌شوند.

## لایه‌های تاریخچه

سه لایه برای جلوگیری از بزرگ‌شدن یک فایل واحد استفاده می‌شود:

1. `data/history.json` — تاریخچهٔ Source-level غنی و Rolling برای ۷۲ ساعت اخیر.
2. `data/consensus_history.json` — تاریخچهٔ فشردهٔ اجماع Karen Fuse، تقریباً یک نقطه در هر ۳۰ دقیقه، برای نگهداری بلندتر.
3. `data/tgju_history.json` — تاریخچهٔ روزانه OHLC از TGJU برای بازه‌های بلند ۷/۳۰/۹۰ روز و یک‌سال.

به این ترتیب دادهٔ تاریخ‌دار Karen Fuse حفظ می‌شود، اما PWA مجبور نیست برای هر مشاهدهٔ قدیمی همهٔ جزئیات تمام Sourceها را دانلود کند.

## نمودار

- دارایی‌ها: طلای ۱۸، دلار آزاد و XAU/USD.
- بازه‌ها: ۱ ساعت، ۶ ساعت، ۲۴ ساعت، ۳ روز، ۷ روز، ۳۰ روز، ۹۰ روز و یک‌سال.
- بازه‌های کوتاه از Snapshotهای Karen Fuse استفاده می‌کنند.
- بازه‌های بلند ابتدا از آرشیو فشردهٔ خود Karen Fuse استفاده می‌کنند و اگر پوشش کافی نباشد به تاریخچهٔ روزانه TGJU برمی‌گردند.
- لمس/Drag روی نمودار Crosshair و قیمت/زمان نزدیک‌ترین نقطه را نشان می‌دهد.
- شکاف بزرگ در جمع‌آوری به شکل خط پیوستهٔ جعلی نمایش داده نمی‌شود.

## Blu

قیمت خرید/فروش Blu همچنان دستی و فقط روی دستگاه کاربر ذخیره می‌شود. نمونه‌های قدیمی V0.3 هنگام Load/Import پشتیبانی می‌شوند و Export جدید شامل این فیلدهاست:

- `timestamp`
- `reference_gold18`
- `blu_buy_quote`
- `blu_sell_quote`
- `note`

Basis از نمونه‌های معتبر اخیر با وزن بیشتر برای نمونه‌های جدید محاسبه می‌شود. ثبت دستی لازم نیست در هر دقیقه انجام شود.

## ماشین‌حساب

Calculator دو حالت **خرید** و **فروش** دارد. کاربر می‌تواند تومان یا گرم را وارد کند و فیلد دیگر بر مبنای قیمت مرجع و کارمزد محاسبه می‌شود.

مرجع می‌تواند:
- اجماع بازار؛
- یا تخمین Blu، در صورت وجود نمونهٔ کالیبراسیون کافی.

پیش‌فاکتور، قیمت مرجع، ورودی، مقدار ناخالص، کارمزد، خروجی نهایی، زمان مرجع، تعداد منابع، Spread و Quality را نشان می‌دهد.

## فایل‌های کلیدی

- `index.html`, `style.css`, `app.js`: رابط موبایل‌محور.
- `calc.js`: هستهٔ تست‌پذیر محاسبات خرید/فروش.
- `scripts/collect_prices.py`: Collector و نرمال‌سازی Schema v2.
- `scripts/test_calc.js`: تست ماشین‌حساب.
- `scripts/test_ui_contract.py`: کنترل قرارداد IDهای UI.
- `docs/DATA_SCHEMA_v2.md`: تعریف Schema داده.
- `.github/workflows/quality.yml`: Syntax، Self-test، Calculator test، UI contract و Probe منابع در PR.
- `.github/workflows/collect-prices.yml`: جمع‌آوری دوره‌ای داده.

## حریم خصوصی

داده‌های Blu، یادداشت‌ها، مرجع دستی و تنظیمات شخصی در `localStorage` دستگاه باقی می‌مانند و به Collector عمومی ارسال نمی‌شوند.
